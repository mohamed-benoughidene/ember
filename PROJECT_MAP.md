# Project Map

This file lists every file and its purpose in the repository. Update it when files or folders are added or removed.

## Root Files
- `.gitignore`: Ignore rules for Python build files and local database files.
- `AGENTS.md`: Rules for AI coding agents working in this repository.
- `CLA.md`: Contributor License Agreement (license-grant style): contributors keep copyright, grant the project a permanent license, signed with a `Signed-off-by:` commit line.
- `Constitution.md`: Core build rules for modules, data, interfaces and tests (AI caveman version).
- `GLOSSARY.md`: Shared vocabulary of the project: knowledge base, ledger, item, link, source, status, proposal, confirm, gatekeeper, sweep, engine, and the backup, export, and restore language. Lists the words to avoid.
- `LICENSE`: Business Source License 1.1 (source-available): free for personal and internal use, commercial license required only for offering Ember to third parties; each version becomes MIT two years after its first publication.
- `Personal guidelines.md`: Rules for tone, accuracy and review style (AI caveman version).
- `PROJECT_MAP.md`: This file. Index of files and their purpose.
- `README.md`: The front page. What Ember is, two small Mermaid diagrams of how it works, a quickstart with settings, which commands send text to an AI service, a one-table command overview (details in `docs/commands.md`), engine status, an FAQ, the license, and the repository layout.

## Python Implementation (`ember/`)
- `pyproject.toml`: Package metadata, locked stack deps (click, openai, pydantic; pytest is a dev dep), the optional `relate` extra (`sentence-transformers`), pytest config.
- `ember/__init__.py`: Package version.
- `ember/__main__.py`: Runs the CLI via `python -m ember`.
- `ember/cli.py`: Click CLI. `capture` runs the full 4-phase pipeline; `capture-source` is the Phase 1 standalone command; `relate` runs all 4 Relate phases (Phase 3 AI propose, Phase 3.5 raw-answer save, Phase 4 gatekeeper + confirm + atomic write, printing one `relate rejected: CODE | detail` line per gatekeeper rejection before the summary) and defines `RelateTerminalConfirm` (raises the relate `UserAbort` on end of input); `set-validated` / `clear-validated` write the Assumption flag; `maintain` runs the Maintain sweep (load + derive + atomic write + report) and then the Phase-5 close proposals on a fresh post-apply snapshot (the free `stale_close_candidates` pre-filter: an empty shortlist prints the `stale:` outcome line and builds no AI adapter, no key needed; a non-empty shortlist prints one pinned proposal block per stale Question and confirms with `[y]es / [n]o / [q]uit` via `MaintainTerminalConfirm`, an accepted close written through the human `validate_close_item` path, raw answers stored in `ai_responses` keyed by `item_id`; `--dry-run` lists the pre-apply shortlist as `item <id>: stale <type> (...) (dry-run)` lines and builds no proposer; `stale shortlist capped at 10 items (list truncated)` before the loop; exit 2 on abort); `close-item` / `set-status` / `reverse-supersedes` are the Maintain human-only mutations (close an item by hand, move it between `Active` and `Challenged`, and undo a `supersedes`); `edit-item` is the Maintain human write for `items.rationale` / `items.source` (`--dry-run` prints the planned old -> new line and writes nothing); `remove-link` is the Maintain human removal of one confirmed link (ONE `Confirmed -> Rejected` status flip plus its `link_removed` ledger row in one transaction, the row never deleted, `--dry-run` prints the pinned flip line and writes nothing, a second removal of the same link exits 1 `MAINTAIN-015`); `undo` / `redo` are the Maintain undo/redo commands over `run_undo` / `run_redo` + `UndoRequest` (undo step 04: `--dry-run` loads and derives only and writes zero rows, the dry-run line names no new group and ends in `(dry-run)`; a real run appends the inverse group and names it via the display-only `_newest_group_id` read, printing the one `format_undo_line` report; any `EmberError` prints `error: <log_line()>` on stderr and exits 1); `db-check` prints the read-only database health report (exit 0 healthy, 1 on `DRIFT` / `UNREADABLE`); `backup` is the thin CLI edge over `create_backup` (argument `target_path`, option `--db`; success prints `backup written: <path> (schema v<N>, <count> items)` with `rotated to <path>` on stderr when an existing target was rotated aside, any `EmberError` prints `error: <log_line()>` on stderr and exits 1, the help text ends with the restore warning); `export` is the thin CLI edge over the export pipeline (option `--out` optional, option `--db`; the DB is opened by `open_query_database` read-only, then gather -> render -> emit, `--out` prints `exported <N> items, <M> links, <K> ledger rows, <S> sources -> <path>`, no `--out` prints the whole rendered text to stdout, the self-overwrite guard runs before any open-for-write and `--out` naming the DB file itself exits 1 `EXPORT-002` with the DB byte-identical, any `EmberError` prints `error: <log_line()>` on stderr and exits 1, the help text ends with the not-restorable warning); `topic-search` takes `--status` `--type` `--limit` on top of `--query` (bad values exit 1 `QUERY-006` with `field`, non-integer limits and unknown flags exit 2 via Click); `history` takes `--limit` / `--offset` / `--since` on top of `--item` (the window composes on both views, a naive or unparseable `--since` exits 1 `QUERY-007` with `since_length`, negative limit/offset exit 1 `QUERY-006` with `field`, non-integer values and unknown flags exit 2 via Click); bridge step 02 appends the two read commands in a bracketed end-of-file section: `list-items` (`--status` / `--type` / `--limit` / `--offset`, the same validators and `QUERY-006` `field=` handling as `topic-search`, printing `{total, items}` with the nine-field spec projection per item) and `show-item` (`--item N`, printing `{item, source, links_out, links_in}` with each link's direction, the other item's coordinates and `reversed_at`; unknown id exits 1 `QUERY-001`); both open `open_query_database` (read-only, floor 10, never migrates) and print one JSON document.

- `ember/maintain/maintain_lookup.py`: The `MaintainLookupPort` protocol (7 reads: items, confirmed links, undo step 04's `list_all_links` — every `links` row ANY status, carrying `reversed_at`, the binding step-03 deviation U3-3 so the undo refusal rule can verify a removed or reversed link — and `has_ungrouped_rows`, reversed link ids, shield log, and undo step 02's `list_grouped_ledger` — only rows with a non-NULL `group_id`, each with its rows in id order. ## Database Tables (SQLite)
- `schema_version`: Holds the applied migration number.
- `sources`: Immutable raw input texts. Columns `id`, `title`, `full_text`, `timestamp`, `content_hash` (unique, the dedup key).
- `items`: Confirmed typed items. Columns `id`, `type`, `statement`, `source_id` (foreign key to `sources.id`), `status`, `created_at`, `validated` (set only on Assumption rows), `rationale` (Decision text), `source` (Finding evidence text), `close_reason` (why closed; one of 5 reasons, NULL when open), `status_origin` (`derived` or `manual`), and `metadata` (nullable project label from migration 012, written by capture, read by relate's metadata signal, NULL means unlabeled).
- `change_log`: Append-only ledger. Columns `id`, `item_id`, `link_id` (foreign key to `links.id`), `field_changed`, `old_value`, `new_value`, `timestamp`, `trigger_cause`, and `group_id` (nullable undo-group stamp from migration 013: one human action's shared id; pre-013, sweep, and capture/relate rows read NULL). Maintain writes `field_changed` values `status`, `status_origin`, `link_reversed`, `rationale` / `source` (`edit-item`), and `link_removed` (`remove-link`); undo step 03 adds the inverse rows (same fields, causes `user_undo` / `user_redo`) plus the pointer markers `undo_of` / `redo_of` and the `link_unreversed` reversal-undo marker.
- `ai_responses`: Raw AI answers, stored verbatim. Columns `id`, `source_id` (nullable foreign key to `sources.id`), `item_id` (nullable foreign key to `items.id`), `response_text`, `timestamp`.
- `links`: Typed directional edges. Columns `id`, `source_item_id`, `target_item_id`, `link_type`, `status` (`Confirmed` or `Rejected`), `created_at`, and `reversed_at` (NULL live, non-NULL reversal timestamp, migration 011; written only by maintain's paired reversal write). Unique per source/target/type.
- `item_embeddings`: Rebuildable vector cache. Columns `item_id`, `vector`, `model_name`, `embedded_at`.
