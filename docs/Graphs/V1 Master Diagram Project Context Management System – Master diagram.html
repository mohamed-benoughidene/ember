V1 master diagram: how Ember works

Ember keeps what a project has decided and learned. It has five parts. The AI only suggests. Fixed checks make sure each suggestion is valid. You decide what is saved.

  • AI suggests
  • Automatic check (no AI)
  • You decide
  • Saved

Words used on this page

Item
One thing Ember keeps: a Decision, Assumption, Finding, or Question.
Source
The original text you gave Ember, kept word for word.
Link
A confirmed connection between two items.
Status
Where an item stands: Active, Challenged, or Closed.
Ledger
The permanent list of every change ever made.
Knowledge base
All items, links, and the ledger, kept in one file on your computer.

How the five parts connect

  1. 1 Captureturns a source into items
  2. 2 Relatelinks items to each other
  3. 3 Maintainflags items that need a second look
  4. 4 Queryreads it all out
  5. 5 Safetybacks up, exports, and checks the file

All five parts work on one place: the knowledge base file on your computer. Parts 1, 2, and 3 save into it. Part 4 only reads. Part 5 copies it, writes it out as text, or checks it. The file also refuses invalid saves, as a second check after the automatic checks.

1Capture

Turns a source into items. You end up with only the items you said yes to.

  1. You decide

    You bring a source

    A chat, a message, or a document. Up to about 5 MB of text.

  2. Automatic check

    Ember stores it

    A full copy is kept word for word. If you bring the same text again, Ember reuses the copy.

  3. AI suggests

    The AI suggests items

    It reads the source. Each suggestion has a type, a short statement, and an exact quote from the source. It can also see up to 50 recent items. This step sends your text to an AI service on the internet.

  4. Automatic check

    Ember checks each suggestion

    Is the type allowed? Is the statement filled in? Does the quote really appear in the source? Is it nearly a copy of an item you already have? That last check only gives a warning.

  5. You decide

    You confirm

    For each suggestion: yes, no, edit, or quit. Nothing is saved until you say yes.

The four kinds of item

  • DecisionA choice the team made. Example: use dark green buttons.
  • AssumptionSomething we treat as true but have not proven. Example: users have fast phones.
  • FindingSomething we discovered. Example: blue buttons failed the contrast test.
  • QuestionSomething we do not know yet. Example: does dark green pass the test?

Where every item stands

  • ActiveStill counts.
  • ChallengedNeeds a second look.
  • ClosedFinished. A closed item always carries a reason, such as answered, found wrong, replaced by a newer item, or expired.

Good to know

  • The AI can be wrong. That is why every suggestion waits for you.
  • Ember has no command that deletes an item.
  • You can store a source without using the AI at all.

Commands: ember capture (needs an AI key) and ember capture-source (no AI).

2Relate

Connects a new item to the items it belongs with. You end up with only the links you said yes to.

  1. Saved

    A new item exists

    It comes from Capture.

  2. Automatic check

    Ember picks items to compare

    It ranks the other items by similar meaning, by items already connected, and by the same project label (or, with no label, a similar date). It skips pairs that already have every allowed kind of link.

  3. AI suggests

    The AI suggests links

    It sees the new item and each candidate. It suggests which ones connect and what kind of link joins them, from the five kinds below. This step also sends text to an AI service.

  4. Automatic check

    Ember checks each suggestion

    Nine checks run. For example: is this kind of link allowed between these two kinds of item? Is it a duplicate? Would it make a loop of replacements? Is the target already Closed?

  5. You decide

    You confirm

    For each suggestion: yes, no, skip, or quit. A no is remembered, so that link is not suggested again. A skip leaves it open for later.

The five kinds of link

  • supportsA Finding backs up a Decision or an Assumption.
  • contradictsA Finding goes against a Decision, an Assumption, or another Finding.
  • depends onA Decision rests on an Assumption, a Finding, or another Decision. An Assumption rests on a Finding or another Assumption.
  • supersedesA newer item replaces an older item of the same kind. The old one is closed.
  • answersA Finding or a Decision answers a Question. The Question is closed.

Good to know

  • The AI sees only the type and the statement of each item. It does not see your sources.
  • Ember refuses any kind of link that is not allowed between two kinds of item, even if the AI suggests it.

Command: ember relate --item N or ember relate --latest. Needs an AI key and an optional extra package.

3Maintain

Keeps items true when something changes. Only items directly connected to the change are marked.

  1. Saved

    Something changes

    You confirm a link, or you close an item.

  2. You decide

    You run the check

    You run the sweep. Closing an item by hand applies the rules at once.

  3. Automatic check

    Fixed rules run

    Ember applies the four rules below. No AI.

  4. Automatic check

    Items change status

    An item becomes Challenged or Closed. All changes are saved together or not at all. Each change adds a line to the ledger.

  5. You decide

    You review

    For each Challenged item you decide: set it back to Active, close it, or leave it.

  6. AI suggests (optional)

    Old Questions

    For a Question whose newest answer is at least 30 days old, the AI may suggest closing it. You confirm each one. At most 10 per run.

The four rules

  • Rule 1: replacedYou confirm that a new item replaces an old one. The old item is Closed.
  • Rule 2: answeredYou confirm that an item answers a Question. The Question is Closed.
  • Rule 3: conflictYou confirm that two items disagree. The item the link points at becomes Challenged.
  • Rule 4: knock-onAn item is closed as wrong or replaced. Items that depend on it become Challenged.

Good to know

  • The effect spreads one step only. If B is Challenged because A was closed, an item that depends on B is not flagged. Check the Challenged list yourself.
  • A status you set by hand is kept until newer links bring new evidence.
  • By hand you can also undo a replacement, edit a reason or a source, and remove a link. A removed link is marked Rejected, never erased.

Commands: ember maintain, close-item, set-status, reverse-supersedes, edit-item, remove-link.

4Query

Reads items back out. Read only. It changes nothing.

  1. You decide

    You pick a way to ask

    The four ways are listed below.

  2. Automatic check

    Ember reads

    It looks at the saved items and links. It never changes them. No AI.

  3. Saved

    An answer comes back

    Structured text that people and other tools can read. Nothing is rewritten.

The four ways to ask

  • Current stateAll items that still count. Challenged ones come first.
  • Topic searchType a word. Items whose text matches come first. It matches words, not meanings.
  • WhyFollow the links from an item to see the reasons behind it.
  • HistorySee what changed: the old and new value, the date, and the cause.

Commands: ember current-state, topic-search, why, history.

5Safety

Protects your knowledge. None of these commands changes your items.

  • BackupSaves a restorable copy of the knowledge base file. It keeps the 3 newest older copies. To restore, copy the backup back.
  • ExportWrites everything as one plain text file you can read without Ember. The same data always gives the same file.
  • Health checkReads the knowledge base file and reports whether it is healthy. It never changes anything.

Good to know

  • Ember has no restore command on purpose. Restoring must never silently overwrite your live knowledge.
  • An export cannot be restored into Ember. That is the backup's job.

Commands: ember backup, ember export, ember db-check.
